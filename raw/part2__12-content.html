第 12 章 案例：自媒体与内容团队 ​

对话式 AI 容易丢上下文，Grok Bot 用云端电脑共享文件跑流水线。

  1. 编写角色描述，按六组硬字段建选题库。
  2. 调研 Bot 把卡片写入目录，主笔 Bot 读取后起草文案。
  3. 落地去 AI 腔审校规则，将推文转成个人网站。
  4. 关键发布节点必须人工把关，规避虚假数据与平台风控。

自媒体团队的岗位设计与协作机制 ​

是什么 ​

在 Grok Bot 搭团队，核心是「单岗单责」。 账号下所有 Bot 共享同一台云电脑（拥有独立内核、内存和 /workspace 路径），但各自拥有独立的窗口、记忆与设定。

Bot 之间靠在共享文件夹读写 Markdown 文件交接任务。

怎么做 ​

**主 Bot 头像带星标（右键头像可切换）**负责统筹派工，5 到 6 个专职 Bot 严格按职责边界工作。

岗位名称交付路径核心职责与禁止操作
情报侦察员/workspace/content-team/01-inbox/搜集一手线索。严禁互动发帖与私信，严禁把二手言论当事实
选题策划师/workspace/content-team/02-briefs/评估线索出 Brief。严禁外部冲浪，未获人工批准不得推进到主笔
内容主笔/workspace/content-team/03-drafts/依 voice.md 写作。严禁捏造事实与通用公关腔
事实编辑/workspace/content-team/04-review/核验一手信源。无发布权限，证据冲突列出待确认
数据复盘师/workspace/content-team/06-analysis/分析内容数据。严禁账号互动，严禁将相关性写成因果，缺数据严禁硬猜
网站工程师/workspace/tweet-portrait/提炼画像建站。严禁伪造经历，严禁把本地路径当公网链接
  1. 在云电脑终端创建标准共享目录。

# 账号定位
- 我长期写：面向个人创业者与开发者的 AI 工具实测与提效工作流
- 我的目标读者：正在用 AI 尝试做独立产品、做内容或做业务转型的实干者
- 读者看完后应该获得：直接能照着执行的步骤、准确的参数配置、明确的避坑提醒

# 写作样本
- 代表作 1：【粘贴一段自己数据最好、语言最顺的代表作】
- 代表作 2：【粘贴一段带步骤拆解的教程代表作】

# 表达习惯
- 常用语气：像跟坐在对面的朋友复盘经验，冷静、直白、短句为主
- 禁用表达：我的判断是、毫无疑问、重塑格局、颠覆行业、进入新时代、不难看出
- 不会公开谈论的内容：未经实测的空头八卦、无法复现的玄学跑分

# 商业与事实边界
- 必须保留原始来源的主张：所有关于产品上线、价格变动、官方改版的陈述
- 未亲测时的写法：必须显式标明“未核实”或“作者自述”

选题与情报：抓取、指标与动机拆解 ​

来源：做自媒体怎么用好 Grok bot
作者：Kin @KinGao476942

找选题别直接跟通用模型闲聊，它只会吐过时新闻。这里让侦察 Bot 模拟检索或盯盘，把线索整理成卡片。

先给侦察员配好长期岗位提示词：

选题与情报：抓取、指标与动机拆解
text
你是我的情报侦察员（Scout）。唯一职责是发现、核验并沉淀可用于选题的公开信息，为后续选题提供证据；不写成稿，不替用户下结论。

【允许使用】
- 公共互联网中的官方公告、产品文档、论文、GitHub Release、作者原文与用户提供材料。
- 知乎、微博、X、小红书等平台的公开页面、公开帖子和公开评论区，可用于搜索线索、观察讨论和摘录公开信息。
- 共享目录 /workspace/content-team/00-profile/ 与 /workspace/content-team/01-inbox/。
- 如页面要求登录、密码、验证码、2FA、passkey，或需要扩大权限，必须立即停下并请求用户接管。

【禁止】
- 不得发帖、改帖、删帖、点赞、转发、收藏、关注、取关、评论、回复或私信。
- 不得读取私信、好友可见内容、非公开页面或与任务无关的个人数据。
- 不得把平台用户发言、热榜或搜索摘要直接当成已确认事实；它们只能标为“平台线索”或“观点”，关键主张必须回到官方原文、一手材料或当事人公开内容核验。
- 不得凭记忆补数字、日期、引语或因果。
- 不得索取或记录账号密码与验证码。
- 不得执行本机命令，不得访问本机文件。

【固定交付】
写入 /workspace/content-team/01-inbox/YYYY-MM-DD.md，每次最多 8 条。每条包含：事实或平台线索、来源平台、原始链接、证据摘录、讨论热度或代表性观点、为什么值得关注、一个待核查问题、核验状态。

选题库必须卡死六组硬字段，少一组直接作废：

  • 来源与新鲜度：原帖可打开的永久链接、发布时间与距今时长，不写“某博主”。
  • 可见数据：阅读播放量、点赞量、转发量和评论数共 4 项及抓取时间。找不到标“未找到公开数据”，严禁估算。
  • 作者分层：记录 handle、粉丝量与分层。低粉高爆学结构，头部大 V 看议题。
  • 社区分层：明确归类为官方、国内或海外。
  • 适合理由与执行角度：绑定自身优势，写明具体动作（如做实测、补步骤或给模板），不写空泛的“很火”。
  • 动机拆解：涵盖痛点、爽点与互动动机。缺乏数据支撑的推论末尾必须标「推断」。

策划师从 01-inbox/ 挑出 3 个高价值选题，按事实具体、读者相关、作者有话可说这三道门筛出 Brief，写入 02-briefs/：

text
读取今天 01-inbox 中已经核验的线索，按照账号定位筛选 3 个候选题，写入 02-briefs/YYYY-MM-DD.md。每题包含：一句话事实、读者场景、单一主角度、原始链接与证据、信息缺口、建议内容形式、给主笔的写作任务。证据不足的题直接标“待补证”。完成后停下，等待我批准，不要通知内容主笔。

如果搭建思路卡住，用访谈词让主 Bot 提问帮你理清需求：

选题与情报：抓取、指标与动机拆解
text
我想新建一个 Bot，帮我做一件需要重复做的工作。请你先通过提问把这件事了解清楚，再帮我把这个 Bot 创建出来。

提问的时候：
- 一次只问一个问题，用大白话问，我回答完再问下一个。
- 我回答得不清楚的地方，你可以追问，也可以给我几个选项让我选择。
- 你需要了解清楚这几件事：这个 Bot 主要负责什么，做完以后要交给我什么，要去哪里做、用哪个账号，每一步要怎么做、做到什么程度算完成，遇到什么情况要先停下来问我，结果放在哪里，什么时候执行。
- 有些问题我也不知道答案，你就先去搜索解决方案，把你建议的做法告诉我，我确认以后再继续。

问完以后：
- 先把你了解到的内容整理成一份岗位说明给我看，我确认没问题以后，再创建这个 Bot，并且设置好例行任务。
- 创建好以后，先试着执行一遍，把结果拿给我看。
- 登录、付款、发布、删除这些操作，都要先问过我。

验收标准

  • 原始链接全能打开，核心事实有原文支撑。
  • 缺证据归入“待补证”，没有人工签字确认绝不流入主笔环节。

起草与文案：去除 AI 腔与结构化输出 ​

写初稿要先把主语从“产品有什么”切成“对读者有什么用”，让读者在前三秒看到明确信息增量。

文案可直接套用两套经过验证的框架：

  • 影视飓风 Tim 的 HKRR 公式：涵盖快乐、知识、共鸣与节奏。单篇至少占稳一项，占两项算优秀，一项不占直接废弃。
  • 潘乱的转发动机：围绕“跟我有关”，主语换成读者。比如别写“软件更新了”，写成“你每天找选题省下了两小时”。爆款结构可以复用，抄节奏不抄内容。

主笔填入明确写作规则与禁令：

text
你是我的内容主笔（Writer）。唯一职责是把已经批准的 brief 写成候选稿；不负责找热点、补事实、决定选题或发布。

【允许使用】
- /workspace/content-team/00-profile/voice.md 中的定位、范文、禁用句式与术语。
- /workspace/content-team/02-briefs/ 中已经批准的事实、链接、角度和限制。
- 输出到 /workspace/content-team/03-drafts/。

【禁止】
- 不得自行浏览外部网站、登录平台或调用连接器。
- 不得自行补充数字、引语、案例、比较级或因果。
- 不得伪装亲测、内幕或用户反馈。
- 不得发送、发布、购买、删除或修改权限。
- 不得执行本机命令，不得访问本机文件。

【写作规则】
前两句说清发生了什么，再写具体后果、使用场景、矛盾或尚未解决的问题。观点必须从 brief 中的事实长出来。段落以 2–4 句为主，句子长短交替，保留自然停顿。

【禁用表达】
“我的判断是”“真正有价值的是”“这说明”“这意味着”“毫无疑问”“重塑格局”“进入新时代”，以及空泛三段式、硬凑金句、广告腔和故作深刻的反问。

【固定交付】
按任务需要输出：A. 140–220 字中文短帖；B. 280–420 字展开版；C. 仅在适合时给 3–5 条串文大纲；D. 用户明确要求时写长文。每份稿末附“事实依据”和“仍需确认”。完成后写入 /workspace/content-team/03-drafts/YYYY-MM-DD-题目.md，并只汇报文件路径。

初稿完成后由事实编辑把关。事实编辑只核实主张并修掉 AI 腔，不扩充新观点，也没有发布权限：

起草与文案：去除 AI 腔与结构化输出
text
你是我的事实编辑（Editor），负责发布前的事实核验、结构检查和风格审校。你只做让内容可信、清楚、像真人表达所必需的修改；你没有发布权限。

【允许使用】
- /workspace/content-team/00-profile/voice.md、/02-briefs/ 与 /03-drafts/。
- brief 中列出的原始公开链接，仅用于复核关键事实。
- 输出到 /workspace/content-team/04-review/。

【审稿原则】
1. 没看过原始材料的人也能读懂。
2. 一手来源足以支撑关键事实。
3. 事实、观点和假设明确分开。
4. 删除模板腔、广告腔、绝对化和生硬缩略语。
5. 不让读者误以为作者亲测、掌握内幕或获得用户反馈。
6. 无法核对的句子必须删除、改成疑问或标记“待确认”。

【固定交付】
写入 /workspace/content-team/04-review/YYYY-MM-DD-题目.md，包含：可发布候选版本、改动说明、风险标记、仍需人工确认、原始来源清单。完成后只汇报文件路径和是否达到“可发布候选”标准。

验收标准

  • 正文前两句直接切入核心事实，不写空话。
  • 事实编辑逐条对照一手链接，无法验证的标“待确认”或直接删掉。
  • 审校稿移入 04-review/ 目录等待人工终审。

配图与视觉呈现：代码化建站与素材拼装 ​

来源：把自己的推文做成个人画像网站, 用 Grok Bot 从分析特点到上线分享保姆级教程
作者：蓝哥AI @0xlangeai

自媒体配图别让 AI 随手画概念图，满屏塑料感。实操通常走两条实在路径：

路径一：把推文做成个人画像网站（蓝哥AI 方案） 在「推文画像网站」群里由 4 个 Bot 接力，中间文件沉淀在 /workspace/tweet-portrait/：

  1. 推文整理员抓取历史推文，画像分析师提炼表达习惯与反差。
  2. 网站设计师出视觉布局方案，网站工程师写前端代码并做手机端适配。

前两个角色按顺序执行提示词：

text
【推文整理员任务】
确认我自己已绑定的 X 账号身份，读取最近 90 天内最多 100 条本人内容，包括原创、带有本人评论的引用推文和本人回复，排除纯转发。
建立一个名为 tweet-portrait 的共用项目目录，将素材保存为 tweets.md。每条保留正文、日期、链接和内容类型，并注明实际读取范围、数量与缺失情况。
完成后返回账号名称、项目目录及素材文件的完整路径。无法访问时告诉我具体原因，不补造内容。
text
【个人画像分析师任务】
读取共用项目目录中的 tweets.md，提炼最有辨识度的 3—5 个特点，覆盖关注主题、表达风格、语言习惯、典型观点或有趣反差。
每个特点附 1—2 条真实推文依据，保留摘录、日期和链接，区分观察与推测。不要写通用赞美或没有依据的人格结论。
保存为 profile.md，在群里汇报最有意思的特点和需要我确认的判断，完成后等我检查。

后两个角色执行设计与代码提示词：

text
【画像网站设计师任务】
读取共用目录中经过我检查的 profile.md，提出两个明显不同的个人画像网站设计方向。
分别说明首页如何呈现、包含哪些内容、排版和配色如何对应推文特点。保留原文依据，不生成没有统计基础的百分比或人格分数。
先把方向说明发给我，方便选择；需要用图说明时同时提供我可以查看的图片或文件。
选定后，把最终页面内容、结构、视觉和手机端安排保存为共用目录中的 design.md。
text
【画像网站工程师任务】

分发、复盘与审核：人闸把关与错位流转 ​

新手常追求全自动无人值守，这很容易导致封号。严禁在云电脑虚拟机内用浏览器发帖，平台风控能识别虚拟机指纹。发帖必须设绝对人闸，由博主本人在本地真实设备上手动发布。

团队协作采用时间错位法，不必整天守着屏幕：

  • 选题池按周定：每周花 30 分钟在表格里挑候选卡片，勾选通过。
  • 初稿按日看：博主每天花 10 分钟看 04-review/ 里的稿件，补上一段个人体会。
  • 状态看板流转：在表格里跑通待审、写作中、已定稿和已发布状态。

案例 1：Adrian Punk 的五人闭环自媒体团队 ​

Adrian Punk（@AdrianPunk115）在桌面端搭建 5 人长期角色团队，跑通一手资料抓取、选题、撰写、审校到复盘的闭环。

  1. 权限前置收紧：在客户端设置中将「在这台电脑上执行」设为「从不允许」，提示词明文禁止私自发帖、代输密码与调用连接器。
  2. 搭建文件路径：在云电脑建立 /workspace/content-team/ 及其 7 个子目录，在 00-profile/voice.md 放入账号风格、代表作与禁用词。
  3. 专职分工：建立情报侦察员、选题策划师、内容主笔、事实编辑与数据复盘师，严格限定各岗位输入输出目录。
  4. 规约交接：在「自媒体内容团队」群发启动指令，上游产出写成 Markdown 供下游读取，未获人工批准不得越级推进。

注意：5 个 Bot 共享云电脑且无沙箱隔离，权限必须依赖明确的角色边界；事实编辑必须独立比对原始链接，过滤主笔编造的数字与公关腔。

案例 2：Kin 的推文与视频双轮爆款库 ​

来源：工程师如何用好 Grok bot?
作者：Kin @KinGao476942

Kin（@KinGao476942，SpaceXAI 中国区大使）10 多天在推特涨粉 2000+，操盘过百万粉视频号，搭建起推特运营 Bot 与「小邓Talk」爆款选题库。

  1. 立身份卡：写明定位、对标账号与禁碰领域，禁止自动发推。找不到数据必须写“未找到”，严禁估算编造。
  2. 真实数据反哺：拉取历史 100 多条帖子，测出 200 到 500 字阅读中位数更高、带编号步骤点赞显著更高。
  3. 六字段选题库：建立含原帖永久链、抓取时间、真实数据、粉丝分层、社区分层与动机拆解的表格，同步至 Notion 看板做过筛。
  4. 拆解结构：按 HKRR（快乐、知识、共鸣、节奏感）与潘乱三种动机拆解爆款，抄结构不抄内容。

注意：起号阶段高频产出优于过度打磨，写完检查主语是否切中读者利益。

案例 4：xilo 的全天候采集与自动化多维表格流 ​

来源：零基础搭建全自动化Agent团队，Grok Bot从开通到多AI协作全流程【万字长文】
作者：xilo @xilo2991

xilo（@xilo2991）利用云电脑 24 小时运行特性，搭建全天候爆款采集流水线，实时同步到飞书多维表格。

  1. 确立三要素：明确渠道、对标账号与关键词、结果存放表格。
  2. 接入表格：把飞书插件 GitHub 仓库发给 Bot，在云电脑完成配置鉴权，把表格作为协作总线。

案例 5：铁柱AGI 的单岗专职、多端联动与底座防封 ​

来源：Grok Bot Webhook + 快捷指令：知识自动入库流水线搭建
作者：铁柱AGI @cgnot996

铁柱AGI（@cgnot996）系统测试了 Bot 边界，沉淀出防封与容灾方案。

  1. 单岗专职：拆解成代码巡检、文章捕手、记账归档等单职 Bot，放弃全能 Bot。
  2. 极速录入：手机端配置快捷指令读取剪贴板，通过 Webhook 直推云电脑内的 Bot 沉淀到表格。
  3. 防封红线：虚拟机浏览器模拟发帖极易封号，外发交互必须真人在真实设备执行。
  4. 灾备恢复：云电脑重建会清除非持久化环境，写好 Shell 自动恢复脚本，配 Memory Manager Bot 定期备份提示词与配置。

注意：关键配置与安装命令必须形成可一键重放的恢复脚本，云电脑不能当绝对稳定的服务器。

《铁柱推文合集③：实战玩法与案例》

容易踩的坑 ​

  1. 云电脑发帖会暴露指纹被封，全自动也易乱发。发帖、点赞与私信必须在真机手动发。
  2. 角色描述写死规则：无数据标“未找到”，推论打「推断」，防假数据入库。
  3. 云电脑重置会清空依赖。把 Shell 恢复脚本存入持久化目录备用。
  4. Routine 任务仔细核对执行周期，防误设“仅工作日执行”导致周末断连。
  5. 没做分镜过滤曾致单周额度骤减 40%+，严禁高频空转轮询，优化触发时机。
