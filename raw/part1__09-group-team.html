第 9 章 群聊与团队 Bot：从一个 Bot 到一组 Bot ​

别把活全塞给一个 Bot，也别拉多个 Bot 进群。多 Bot 容易互相接话、循环唤醒并耗尽整周额度，个人 Bot 进 Slack 也无法协同。

  1. 用统筹 Bot 作单一入口，靠本地与云电脑共享文件交接任务。
  2. 需要全员共享经验时，发布团队 Bot。
  3. 依 2026-10-12 生效的 The X Subscription 统一订阅机制控好用量。

群聊机制与交互规则：多 Bot 如何在同一对话中协作 ​

群聊可拉多 Bot，但团队 Bot 无法与本地 Bot 放同一群。

发消息默认全员回，指定用 @Bot名称。复杂任务中 Bot 的私聊交接不同步到群里。

怕私聊太散，直接立规矩：

  • 临时约束：群里发指令。
text
就在群里回复，这件事不要私信我。
  • 长期约束：让它记入长期记忆。
text
记住：在群组聊天中，要在群里回复。

系统没有一键禁互聊开关，防连环调用浪费额度有这几招：

  1. 临时禁令：群里发指令。
text
不要给其他 Bot 发消息，先问我。
  1. 长期规则：要求未经确认严禁私下唤醒其他 Bot。
  2. 紧急叫停：停不下来时，进它的专属私聊叫停。
  3. 辅助静音：关通知，或侧边栏右键 Hide from sidebar。

管理与限制：

  • 改名与换方向：右键 Rename chat（手机端点群名 Edit name）；换方向直接群里说明。
  • 功能限制：群聊完全不支持语音（只能单聊），无法对单个 Bot 开关通知。

验收标准：

  • 成员在 3 个以内，职责无重叠。
  • 提问用 @ 精确唤起。
  • 输出集中在群内，无多余私聊。
  • 未出现 Bot 间连环唤醒。

Bot 间通信与 Slack 权限路由 ​

Bot 只有在代表具体某个人时，才能跨机器人发消息。 个人 Bot 在公开 Thread 里没有代表权，无法唤醒其他 Bot；团队 Bot 在被 @ 时承接提问者身份，把任务转交给他自己的专属 Bot，再把结果发回同个 Thread。

Bot 类型提问位置跨 Bot 权限代表谁回复位置
个人 Bot应用内私聊 / Slack 私信能发个人应用内聊天窗口（非 Slack）
个人 BotSlack 公开 Thread不能发（提示无法执行）无人原消息串
团队 BotSlack 频道 / 私信能发（转给提问者专属 Bot）提问成员发回同个 Slack 消息串

详细规则可见官方文档。

团队 Bot 接入与排坑 ​

  1. 团队 Bot 发布后，所有者点击聊天顶部 Bot 名称，在 Bring to your team's Slack 点击 Connect（未发布时显示灰色的 Connect after publishing）。
  2. 界面若提示 Awaiting admin approval，说明开启了安全管控，联系管理员审批；状态变为 Connected 即绑定成功。
  3. 团队成员使用前须在客户端 Settings > General > Team Bots 点击 Link 绑定账号。 未关联就直接在 Slack 发消息，Bot 只会回复绑定提示。

验收标准 ​

  • Slack 频道内的多 Bot 协作由团队 Bot 统一调度。
  • 团队成员完成账号 Link。
  • 任务在 Thread 内部闭环，没有脱节或权限报错。

团队 Bot 全流程配置：创建、发布与跨人共享 ​

团队 Bot 由成员创建并全员共享，私聊相互隔离。它只在云端运行，不能绑在本地。参考官方指南。

创建与转为团队 Bot ​

  1. 侧边栏点 New chat（+），选 Create new Team Bot。
  2. 交代需求，配置公开插件、Secrets 与文件。
  3. 改名并填写 About。若保留默认名且描述为空，其他成员在列表里搜不到该 Bot。
  4. 点击卡片上的 Publish to Team。

已有个人 Bot 可在界面点 Share > 发布到团队克隆独立副本，生成 Slack 账号，按需迁移机密、记忆与例程（Routines）。

查找与调用 ​

  • 搜索与列表：在 New chat（+）选团队 Bot 浏览，或在搜索框输入名称前 3 个字符。
  • 链接直达：右键选 Copy link。全员共用底座与记忆，非克隆模板。
  • 批量派发：管理员在仪表盘 Manage Team Bots 勾选 Auto-add。被勾选成员侧边栏自动置顶且无法隐藏。

权限与运行机制 ​

调用个人账户时触发 Allow 授权（Allow once 仅本次，Always allow 始终允许，Skip 跳过）。重置进 Settings > General > Team Bots 点 Clear。

审批卡片只在所有者私聊弹出。群聊与 Slack 中 Bot 只能自主运行。

场景运行环境
私聊默认个人云电脑（隐私严则分隔离机）
Slack / 群聊专属共享虚拟机

验收标准 ​

  • 名称与岗位描述清晰。
  • 所有者机密隔离完好。
  • 3 字符检索或链接可唤起。
  • 跨人调用触发 Allow 授权，无越权隐患。

1+N 主 Bot 派活模式：单入口与履约章程 ​

别让所有 Bot 都对接用户，免得你在窗口间传话，群聊也白耗 Token。

推荐采用 1+N 模式，你只跟统筹主 Bot 沟通，由它拆解、派活与汇总，详见 《从一个 Bot 到一整个组织，Grok Bot 的进阶用法分享：本地电脑、AI 分工和知识库怎么接起来》。

主 Bot 六行章程与专职边界 ​

主 Bot 只负责路由与监督，绝不能亲自写长代码或长文。 在 Profile Description 写入六行章程，使其无事静默、有事派活，超长汇报存为文件。

团队组织规范参考 《4.2 团队编排：章程、岗位与放权》。

text
Own: 负责需求的统一拆解、分派、汇总与五行简报汇报。
Sources: 人工下发的指令、项目看板文件。
Output: 纯文本状态摘要，超出五行时输出为指定文件路径。
Approval: 任何对外通信、采购、删除操作必须暂停等待确认。
Failure: 下游专职 Bot 报错时如实上报，不使用过期数据假装完成。
Never: 永远不直接编写业务代码，不擅自修改生产配置。

专职 Bot 须在 Description 写死负向边界：

  • 广告投手 Bot：分析数据并出具待批清单，绝不碰后台与出价，不调预算，也不加词或建组。
  • 文案创作 Bot：只出草稿文件，严禁调接口直接上线公开内容。
  • 竞品调研 Bot：前台只看不动，严禁下单加购，也不留评或向卖家提问，防反爬封禁。

投放专员直接套用提示词模板。

text
Own: 负责广告投放数据诊断与策略输出。
Sources: 运营分析文件 /workspace/project/ad_data.json。
Output: 待批操作清单 /workspace/project/pending_actions.md，列出出价建议与预期影响。
Approval: 绝不直接写入广告后台，不修改出价，不修改预算，不加否定词，所有操作必须等待人工审批。
Failure: 数据缺失时明确标注缺失字段，不推测填充。
Never: 绝不执行任何后台写入与线上提交操作。

待批清单与验收 ​

专职 Bot 只输出结构化待批清单，把决定权留给人工。 比如主 Bot 汇总出 5 条广告出价冲突项，你回复“确认建议”或批注修改后才触发下一步。

系统达标后按三项标准验收：

验收项达标标准
交互与主 Bot单入口清晰运行；主 Bot 不写长代码、不写长文章
专职 Bot各司其职，只产出结构化清单
高风险动作不可逆操作均有明确人工确认卡点

交接文件约定：以共享文件系统替代对话历史 ​

别让 Bot A 在聊天窗贴结果再给 Bot B 读。窗口交互会快速撑爆上下文且容易丢失历史，各 Bot 对话在底层逻辑隔离，根本没法互相检索。

维度特征与包含内容
物理共享层同账号下所有 Bot 共用虚拟机、/workspace 目录、连接器与公共 Skill 库。
逻辑隔离层对话历史互不可见，Bot A 无法调取 Bot B 与用户的私人对话。

物理磁盘既然共享，传递任务就靠本地结构化文件，对话框只用来同步状态与路径。

文件交接流水线标准 ​

标准交接包含落盘、传路径，再到读取与归档。

文件交接流水线标准
[用户指令] ──> (主调度 Bot)
                   │
         1. 派发任务 (指定输出路径)
                   │
                   ▼
             [专职 Bot A] ──> 写入 /workspace/proj/data.json
                   │
         2. 交付：仅返回文件绝对路径
                   │
                   ▼
             (主调度 Bot)
                   │
         3. 调度下发 (附带输入路径)
                   │
                   ▼
             [专职 Bot B] ──> 读取 data.json ──> 写入 output.md
                   │
         4. 汇总简报至用户
  1. 任务派发：主 Bot 明确指定交付绝对路径，如 /workspace/project-alpha/data.json。
  2. 数据落盘：专职 Bot A 跑完清洗写入文件，在对话框只回一句话通知保存路径。
  3. 路径传递与读取：主 Bot 唤醒 Bot B 并传递路径，Bot B 读盘分析后把结论写入 /workspace/project-alpha/report.md。
  4. 交付呈现：主 Bot 提炼摘要，附上本地或云文档链接供审查。

推文画像流水线也是这套模式，整理员抓取存入 tweets.md，分析师读文件提炼标签写入 profile.md，设计师输出 design.md，工程师据此写代码并给预览截图。

实操参考 《4.2 团队编排：章程、岗位与放权》。

接入飞书云文档实现可追溯交付 ​

需要团队协作或批注时，给虚拟机配飞书 CLI 把 Markdown 发为云文档。它自带独立链接方便分发，支持逐段批注，也能保障企业数据安全。

工作流达标包含这几项要求：

  • 链路中每个 Bot 都能独立读写 /workspace 下的固定文件。
  • 对话框只传输状态提示与文件绝对路径。
  • 出现异常时，检查对应磁盘文件即可复现定位。

用量影响与额度控制：The X Subscription 下的多 Bot 治理 ​

2026-10-12 起 Grok Bot 纳入 The X Subscription，统一按周共享额度。

档位价格
Premium$30/月
Super$100/月
Ultra$200/月

规则与防烧策略 ​

  1. 回复与握手消息都计费。私聊团队 Bot 扣自己额度，群聊扣发起方的，周初耗尽整周停摆。
  2. 群聊 Bot 压在 3 个以内，坚决用 1+N 串行替代自由群聊。
  3. 清洗等轻任务用基础模型，核心推导才用顶级推理模型。
  4. 没跑稳前别设半小时或每小时的定时例程，防夜间重试上百次耗尽额度。

验收标准 ​

  • 周额度平稳消耗，没有夜间死循环。
  • 模型分层分明，费用分摊到具体提问者。

实战案例：企业专家经验固化与跨境团队 1+N 落地 ​

SpaceXAI 团队 Bot ​

n2parko 团队让业务专家亲自配 Bot 规则，做成全员共享助手。

  1. 抓高频节点：数据团队做 Databot 查数据湖，避免重复打扰专家。
  2. 扩充岗位：配置 10x Engineer、Marketing 及查 Salesforce 的 Sales Assistant（辅助 SDR/AE）。
  3. 记忆分层：全局沉淀通用规则且保留个人偏好，详见 《Meet your Team Bots｜n2parko》。

跨境 1+12 编排 ​

Zach（@1999Zach22）以 1 船长带 12 岗位，自动化闭环必须设待批清单，严控写权限。

  1. 本地部署：专用 Skill 在本地调顺后，统一部署到云电脑。
  2. 负向边界：投手严禁操作后台仅提建议；调研买家号严禁加购、提问和留评。
  3. 单入口交互：每天汇总简报，遇冲突出 5 处冲突待批单，确认后执行。
  4. 报表沉淀：用飞书 CLI 把报表落成云文档持久链接，详见 《从一个 Bot 到一整个组织，Grok Bot 的进阶用法分享：本地电脑、AI 分工和知识库怎么接起来》。

容易踩的坑 ​

  1. 用三个词界定不了独特技能的，收拢为主 Bot 的 Skill。别一口气建七八个职能模糊的助手，免得整天在窗口间切换。
  2. 同账号所有 Bot 共享云电脑虚拟机、本地路径和浏览器登录态，共享 Bot 切勿存个人私有凭证。
  3. 群指令别太宽泛。Bot 互相客套确认会狂扣额度，可能半天耗完一周调用量。
  4. 别留着 New team bot 默认名且不写描述就发布，其他成员在搜索列表完全看不到它。
  5. 团队 Bot 和本地 Bot 进不了同个群，群里也没语音入口。有这类需求必须切到单 Bot 私聊。
  6. 写上千行代码会填满上下文并失去全局视野。主 Bot 必须只负责调度与督办，落地动作交由专职 Bot 执行。

做完怎么验收 ​

  1. 主 Bot 路由：发跨模块业务指令，主 Bot 须准确复述目标并列出专职 Bot 路径，无外部状态变化时保持静默。
  2. 群聊防互发：下令要求“不要给其他 Bot 发消息”，Bot 只在群内回复，绝不私聊窗口弹消息，也不私下互唤。
  3. 检索与授权：换成员 Cursor 账号在 New chat > 团队 Bot 搜前 3 个字符；调插件必弹出含 Allow once、Always allow 与 Skip 的授权卡片。
  4. 文件交接：A 将中间文件存入 /workspace，Bot B 只凭绝对路径独立跑完，全程无需人工复制。
  5. 人闸拦截：下达发布、后台修改或删除指令，Bot 必须中止执行并输出待批清单，未经人工审批绝不线上写入。
